async cocotb_benches.dau_row_unpack_slots_tb.every_slot_reads_its_own_packed_row(dut)¶

The stride test, stated directly.

One beat, every slot carrying a different key. A tile whose slice stride is hardcoded emits SLOTS copies of slot 0 and passes any test built on a uniform batch; here the keys are all distinct, so it cannot.

async cocotb_benches.dau_row_unpack_slots_tb.random_field_maps_match_golden(dut)¶

Sweep field maps, not just the q6 one: an offset/width/sign combination is what a hardcoded slice gets wrong at a width other than the one it was written against.

async cocotb_benches.dau_row_unpack_slots_tb.ragged_tail_pads_pass_through_unsliced(dut)¶

A row count that is not a multiple of SLOTS is padded by the host with the reserved all-ones packed word. It must emerge as the reserved all-ones PAD quad row – NOT as whatever the field descriptors would slice out of it – so the wide-row tiles downstream drop it by the convention they already implement.

cocotb_benches.dau_row_unpack_slots_tb._packable_specs(rng)¶

A random field map this tile will accept at the configured SLOTS.

_random_specs happily fills all 64 bits, and at SLOTS > 1 a layout with no spare bit is refused as a bad config precisely because it could forge the all-ones PAD. Draw again until there is headroom rather than weakening the constraint – the rejection is the point.

async cocotb_benches.dau_row_unpack_slots_tb.bypass_short_final_beat_is_not_torn(dut)¶

REGRESSION. At SLOTS == 1 an input beat is half a quad row, so input_last on phase 0 really is a torn row. At SLOTS > 1 the beat holds SLOTS/2 WHOLE quad rows, and a batch with an odd number of rows ends exactly there – rejecting it as torn refuses a well-formed stream.

The generalization inherited the SLOTS == 1 rule unchanged, so this passed review and simulation until an independent reader asked what phase 0 MEANS when a beat carries whole rows.

async cocotb_benches.dau_row_unpack_slots_tb.a_layout_that_could_forge_the_pad_is_rejected(dut)¶

REGRESSION. The all-ones packed word is the ragged-tail PAD at SLOTS > 1. A field layout covering all 64 bits can PRODUCE all-ones from real data – four unsigned 16-bit fields at max – and that row would be dropped by the wide tiles. The same input unpacks normally at SLOTS == 1, so the ANSWER WOULD DEPEND ON OUT_WIDTH.

Rejecting the layout makes the sentinel unreachable by construction rather than by convention. Every real packing has room: SF1 q6 is 56 bits, q1 is 41.

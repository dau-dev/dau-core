test_cores.committed_hdl(hdl_dir: pathlib.Path) → set[str] | None¶

The HDL git CARRIES under hdl_dir, as paths relative to it, or None when there is no repository to ask.

Committedness is a git fact, and only git can answer it. A directory listing cannot: the suite renders every generated core into the render root on each run (conftest._render_generated_cores), so a rendered file being PRESENT there is the normal state and says nothing about whether someone checked it in. Absent a repository – an installed distribution – nothing is committed and there is nothing to check.

test_cores.test_every_hdl_file_belongs_to_exactly_one_core() → None¶

Checked-in HDL and registry entries match exactly, in both directions.

A GENERATED core is excluded because it has no checked-in file by definition – and asserted to have none, which is the same guard from the other side: a generated core with a file beside the entry means someone committed rendered output, and whichever of the two is stale will be the one that gets synthesized.

The reach is the whole package, not one directory listing. Listing hdl/ alone left the render root – a SUBDIRECTORY of it – outside this guard entirely, and three rendered tiles sat committed there until a rename made their filenames disagree with their contents. So the walk descends, and the committed set comes from git: a rendered file being present in the render root is the normal working state (the suite renders there on every run), and what distinguishes that from the mistake is whether it was checked in.

test_cores.test_the_canonical_palette_is_exactly_the_registered_names() → None¶

THE GUARD a rename has to pass. A name that leaves this set takes every recorded canonical spec that spells it with it.

Scoped to own_cores() like every exact set here: a vendor’s installed tile is not in our canonical alphabet’s history and cannot depart from it.

There are exactly two honest ways past a DEPARTURE failure:

  1. Keep the name. A rename that buys nothing is not worth an identity boundary.

  2. Bump SPEC_CANONICAL_VERSION and CANONICAL_PALETTE_VERSION in the same change, so every text recorded under the old palette is refused by version instead of read against a registry that cannot resolve it. Designs already on silicon do not re-enter the design cache across that boundary – their hash is stamped in a bitstream and the manifest recording it must not be rewritten – so they are rebuilt once, deliberately, rather than mis-recognized forever.

test_cores.test_dispatcher_rate_still_needs_record_aware_modeling() → None¶

The dispatcher’s framing-shaped rate describes a 2-word record. Record shape is now declared for detection, but this pins the remaining rate-model gap so RECORD_WORDS != 2 is not silently treated as resolved.

test_cores.test_a_core_resolves_hdl_from_the_package_that_declares_it(tmp_path, monkeypatch) → None¶

A tile contributed by another distribution finds its own HDL.

The registry is a hydra search path, so any package joining it through the hydra.lernaplugins entry point can contribute cores. Their HDL used to be resolved under dau_core.hdl regardless, so a third-party tile could be registered from anywhere but had to vendor its Verilog into this package. source_package is the seam.

test_cores.test_a_well_formed_vendor_tile_does_not_trip_our_palette_guards(monkeypatch) → None¶

Installing a third-party tile must not fail THIS suite.

Four guards here assert an exact set over the whole registry – the HDL directory listing, the descriptor-tagged operators, the envelope-free tiles, and the scalar-envelope holdouts. Each is a statement about dau-core’s own palette, and each read loaded_cores(), so a vendor tile registered through the entry point showed up as drift in all four. A contributor’s first experience of the platform was our test suite failing on their correct tile.

The line drawn is between those four and the universal-property guards (every operator has a golden, a contract kind, record words, a measured envelope). Those are contract requirements a well-formed tile satisfies, so they stay registry-wide on purpose – which is why the tile below is built well-formed rather than minimal. It is the exact-set guards that fail even a perfect vendor tile, and only those are scoped.

test_cores.test_a_measured_point_matches_a_derived_clock_period() → None¶

A clock period is DERIVED (1000 / job_clock_mhz), so exact float equality is the wrong test.

150 MHz gives 6.666666666666667 while a registry writes 6.66667: the same physical clock, and the lookup refused it as unmeasured while printing the point it had just rejected. Real clock tiers differ by more than a nanosecond, so a picosecond tolerance keeps the “never a neighboring point” guarantee intact while tolerating representation.

A declared source that does not resolve is a DECLARATION error.

An out-of-tree tile whose HDL directory is not an importable package resolves to a MultiplexedPath that prints the right path and does not exist, so the first symptom used to be a synthesis run against a missing file. The requirement – an __init__.py beside the .sv files, so importlib can traverse the directory – is stated in the error rather than left to be discovered.

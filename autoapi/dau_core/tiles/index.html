dau_core.tiles¶

Tile catalog models: what a query can ask the device for.

A tile is a logical operation. It states the polars shapes it answers and the chain of cores that computes them, with the config port each input arrives on and the field each core writes. A core is one HDL building block (dau_core.cores.CoreDefinition); the same core serves several tiles, and a tile may chain several cores.

The catalog lives in dau-core’s hydra config tree (dau_core/config/dau-tiles/tiles.yaml), composed into the ccflow ModelRegistry at /dau-tiles/<name>. A contributing package declares its tiles in its own composed group, as it does its cores.

How lanes are arranged is not a tile: replication behind the key dispatcher, the range partitioner ahead of sorter lanes and the front unpacker are chosen when a design is priced.

class dau_core.tiles.TileInput(/, **data: Any)¶

Bases: dau_core.models.CheckedModel

Where a core takes one input.

ports are config ports: field selects for a column, value ports for a literal. A literal list or a column tested more than once names one port per use. mask is a config port with one bit per row field. shift and width place a column packed into a field with others: the config port taking its bit offset and the module parameter fixing its width, beside the field select in ports when the core has one. parameter is a module parameter the value fixes when the design is built. source is an input that arrives without a config port.

In the catalog a single port is written as its name and several as a list (TileCore.taken()).

class dau_core.tiles.TileCore(/, **data: Any)¶

Bases: dau_core.models.CheckedModel

One core in a tile’s chain.

wide is the core doing the same job on the wide row stream, with the same config ports. as tells two uses of one core apart (label). inputs maps a placeholder of the tile’s shapes, or an earlier core’s output, to where this core takes it: a config port’s name, a list of them, or a TileInput. config holds config ports at a fixed value, by the operator’s name or as an integer; a list is the values the staging chooses between. derived are config ports set from how the table is staged and params module parameters sized from the staged data, each with what sets it.

class dau_core.tiles.TileExpression(/, **data: Any)¶

Bases: dau_core.models.CheckedModel

One polars shape a tile answers, as polars source text.

expression is an expression over placeholder columns ('pl.col("value") < pl.col("bound")'). frame is a query over a placeholder frame, for a shape an expression cannot state: a group-by, a join against other, a sort or a row limit ('frame.sort("key", descending=True).head(k)'). Either may read the tile’s arguments as bare names. config holds the config values this shape selects (the operator), keyed by port, or by label.port in a tile with more than one core.

class dau_core.tiles.TileDefinition(/, **data: Any)¶

Bases: dau_core.models.CheckedModel

One logical operation: the polars shapes it answers and the cores that compute them.

Every shape of a tile runs on the same chain; they differ in the config values they select. Two chains answering the same shape are two tiles, and the compiler chooses between them.

literals are the placeholder columns that match a literal in the query; any other placeholder column matches a column, or a sub-expression another tile computes first. arguments are the bare names a shape reads where polars takes a number (a window size, a row limit). result says what a lane ending in this tile returns to the host and anything the host finishes.

scale_invariant is a promise a compiler needs before it runs a row expression over fixed-point columns: f(k*x, k*s...) == k*f(x, s...) for k > 0, so computing on the staged integers and decoding gives what polars computes on the values. True of a clip, false of a product.

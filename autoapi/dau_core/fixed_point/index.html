dau_core.fixed_point¶

Integer models of the fixed-point transcendental datapaths.

Two layers, and the distinction is the whole accuracy contract:

  • exp_reference() is the MATHEMATICAL answer – true exp correctly rounded to the fixed-point format. It is what “right” means.

  • ExpDatapath is an ALGORITHM: a specific range reduction, table and polynomial at a specific internal precision. The HDL mirrors it exactly, so the cocotb benches compare against it with zero tolerance, like every other tile in the package.

An operating point that deviates from the reference does so by a MEASURED amount, swept exhaustively over every representable input and recorded in the registry beside the resource envelope. Accuracy is a measured fact here, not a claim – sampling reported one configuration as flawless when an exhaustive sweep found three wrong inputs, so nothing is believed without the full sweep.

See dau-docs-private/design/transcendental-tiles.md for how the operating points were chosen.

class dau_core.fixed_point.ExpDatapath(/, **data: Any)[source]¶

Bases: dau_core.models.CheckedModel

One operating point of the exp datapath.

x is reduced as k/2**table_bits units of ln2 plus a residue, the table supplies 2**(j/2**table_bits), and a Horner polynomial of degree evaluates exp(residue) – all in internal_bits fractional bits.

round_steps rounds each Horner step instead of truncating it, which costs an adder per step in hardware. It buys accuracy only where the internal precision is the binding constraint; past that the polynomial degree binds instead and rounding changes nothing.

class dau_core.fixed_point.LnDatapath(/, **data: Any)[source]¶

Bases: dau_core.models.CheckedModel

One operating point of the ln datapath.

x is normalised to m * 2**e with m in [1, 2), so ln(x) = e*ln2 + ln(m). The mantissa’s top table_bits index two tables – ln(1 + j/N) and the reciprocal 1/(1 + j/N) – reducing the residue to |v| <= 1/N before a short Horner series for ln(1+v). The reciprocal table is what keeps the polynomial degree low without a divider: a direct series on [0,1) would need many more terms.

The exponent term is EXACT integer work: e is a small signed integer and ln2 a constant, so the only approximation is the mantissa series.

class dau_core.fixed_point.NormalCdfDatapath(/, **data: Any)[source]¶

Bases: dau_core.models.CheckedModel

One operating point of the normal-CDF datapath.

Folds on symmetry (the CDF of -x is one minus the CDF of x), so only the positive half is approximated, then evaluates a PER-SEGMENT Taylor polynomial: the magnitude’s top table_bits select a segment and the coefficients are the CDF’s derivatives at that segment, which have closed forms in the density. Piecewise rather than one polynomial because the CDF has no useful global series.

Saturation is exact rather than a clamp: beyond the domain the correctly rounded answer IS 0 or 1, so this tile is TOTAL and needs no error path – the one transcendental here that does not.

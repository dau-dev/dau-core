.. py:function:: test_handle_table_aperture_is_word_aligned_and_shares_no_address()

   The handle aperture the composed scan shell decodes. Its offsets are
   the generator's, and they sit in free window space: above the capability
   block, below the lane block, overlapping nothing the base register map
   defines. An aperture laid over the static pipeline block would decode
   correctly (a shell is one personality or the other) but would leave every
   address in it meaning two things, which is a thing to remember rather
   than a property to rely on.


.. py:function:: test_handle_table_aperture_matches_the_generator_that_emits_it()

   The register contract lives here, but the ADDRESSES are decoded by
   what dau-build emits: a disagreement is not a crash, it is a host writing
   a length into a generation. Pin them against the generator's layout.

   Imported outright rather than skipped around: a guard that skips when the
   other side of the contract is missing reports the same green as one that
   checked, which is how this ran for exactly nobody while the aperture was
   being placed. The develop extra installs the dau-build this is written
   against, so a missing generator is a broken environment, not a reason to
   pass.

.. py:function:: test_the_addresses_of_the_deleted_registers_are_unmapped() -> None

   0x0010 and 0x0024 carried SHELL_VERSION and DMA_CONSTRAINTS, which no
   generator ever stamped, so every host read returned zero. A register
   nothing writes is not a capability. They are gone from the offsets, and
   the identity block falls through to all-ones there -- which the driver
   already reads as 'not advertised' rather than as a value.
